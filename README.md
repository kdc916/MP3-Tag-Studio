# MP3 Tag Studio v1.2.1

단일 HTML 파일로 MP3 파일의 ID3 태그를 편집하는 로컬 도구입니다. 프로그램 설치는 필요하지 않으며 Chrome / Edge 사용을 권장합니다.

## 시작
1. `index.html`을 브라우저에서 실행합니다.
2. `+ MP3 추가`로 파일을 불러오거나 (지원 환경에서는) `+ 원본 수정용 열기`를 사용합니다.
3. 곡명·가수·앨범 정보를 수정하거나 음악 정보를 검색하고 **태그 적용**을 클릭합니다.
4. 앨범아트 영역에 실제 이미지가 나타나는지 확인합니다. 검색 결과 화면의 작은 썸네일만으로는 아직 MP3에 표지가 들어간 것이 아닙니다.
5. `저장 전 태그 검사`로 `앨범아트 포함 확인`을 확인합니다.
6. `다른 이름으로 저장` 또는 `원본 덮어쓰기`를 선택합니다.

## 앨범아트/가사 저장
- JPEG/PNG/WebP/AVIF 이미지를 불러올 수 있습니다(브라우저 디코더 지원에 따라 다름).
- 저장 시 앨범아트를 최대 1000px의 **JPEG** 이미지로 정규화하여 ID3v2.3 `APIC` 프레임에 저장합니다. 원본 JPEG가 작고 유효하면 그대로 사용합니다.
- 일반 가사: `USLT`, 시간 동기화 가사: `SYLT`. 일부 플레이어는 동기화 가사를 표시하지 않습니다.
- **검사 결과**: 저장 예정 MP3의 ID3를 다시 읽어 곡명과 표지가 기록되었는지 확인합니다. 원본 직접 저장은 실제 파일을 다시 읽어 검사합니다.
- 앨범 이미지를 자동으로 가져오는 데 실패했다면 **검색 이미지 열기**를 눌러 이미지를 저장한 후 **이미지 변경**으로 직접 선택할 수 있습니다. 웹 서비스의 접근 정책에 따라 자동 이미지 다운로드가 막힐 수 있습니다.
- 브라우저 내장 오디오 재생 바는 원래 앨범아트를 표시하지 않습니다. 편집기 화면 상단의 표지 미리보기를 확인하세요.

## v1.2.1 디스크 캐시 오류 수정
- `An operation that depends on state cached in an interface object ...` 오류를 해결하기 위해 저장 대상 원본 파일을 **독립된 메모리 Blob으로 완전히 읽은 다음에만** 파일 쓰기를 시작합니다. 원본 File.slice() 참조를 유지한 채 동일 파일을 덮어쓰지 않습니다.
- 음원 플레이어의 원본 파일 접근을 닫고 URL을 해제한 뒤 쓰기 시작하며, 완료 후 다시 `getFile()`로 최신 MP3를 읽어 태그와 앨범아트를 검증합니다.
- 원본이 바뀌었다면 덮어쓰기를 중단합니다. 핸들이 연결된 곡에는 **원본 다시 읽기** 버튼을 제공하며 제목·가수·가사·앨범아트 편집값은 유지합니다.
- 저장 완료 후 검증에만 실패한 경우에는 성공으로 단정하지 않고 **디스크 확인 필요**를 표시합니다.
- 메모리 안정성을 위해 768MB 초과 파일에 대해서는 직접 덮어쓰기를 중단하고 별도 다운로드를 안내합니다.

## 원본 덮어쓰기 동작

**직접 원본 덮어쓰기 가능**: 쓰기 가능한 파일 시스템 API가 있는 Chrome/Edge의 지원 환경(일반적으로 HTTPS 또는 localhost). 원본 재선택 → 쓰기 권한 → 원본 일치 확인 → 최종 확인 → **파일 데이터 독립 복사 및 태그 생성** → 재검사 → 음원 재생 잠금 해제 → 파일 쓰기 → 디스크 재검증 순서입니다.

**직접 원본 덮어쓰기 불가**: `원본 덮어쓰기`가 `같은 이름으로 저장 ↓`으로 표시됩니다. 해당 기능은 수정된 파일을 **원본과 같은 이름으로 다운로드**만 합니다. 원본이 자동으로 변경되는 것은 아닙니다. 다운로드 폴더에서 기존 MP3 파일을 직접 교체해야 합니다. 브라우저는 중복 파일명에 `(1)`을 붙일 수 있습니다.

읽어들인 파일이 원본 파일과 다르거나 중간에 원본이 변경되었다면 안전을 위해 직접 덮어쓰기를 중단합니다. 장치나 폴더에 쓰기 권한이 없으면 브라우저가 이를 차단할 수 있습니다.

## 음악 검색
Apple Music (JSONP 우선), MusicBrainz, LRCLIB. YouTube 결과를 앱 안에서 가져오려면 **사용자 본인의 YouTube Data API 키**가 필요합니다. 각 외부 서비스가 응답하지 않거나 CORS로 차단되면 결과를 보장할 수 없습니다. 파일 오디오는 검색 서비스로 업로드하지 않습니다.

## 테스트 범위
- Node.js 모의 FileSystemFileHandle 테스트: 최초/연속 2회 원본 저장, 외부 파일 변경 시 저장 차단, 원본 다시 읽기, 태그/앨범아트 확인 PASS.
- 외부 Mutagen: 실제 MP3 테스트 출력에서 한글·이모지 제목, 가수, JPEG APIC 정상 확인.
- Chromium headless는 현재 실행 환경에서 로컬 페이지 탐색이 차단되어 실제 Chrome 사용자 클릭 테스트는 미검증. 파일시스템 핸들은 Node 모의 객체로 검증.

- 자체 Node.js 테스트: ID3v2.3 인코딩·검증, JPEG 앨범아트, 쓰기 가능한 파일 핸들 덮어쓰기, 미지원 환경 대체 저장, 다른 파일 덮어쓰기 거부.
- 외부 Python Mutagen 재파싱: 실제 생성된 MP3의 `TIT2`와 `APIC image/jpeg` 읽기 성공.
- 제한: 이 실행 환경의 브라우저가 로컬 페이지 접근을 차단하므로 실제 UI 클릭 및 개별 사용자의 음악 플레이어 화면까지는 검사하지 못했습니다.
